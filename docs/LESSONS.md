# 開発メモ（過去の失敗と教訓）

## 画面の幅は、端末の画面幅より狭いことがある

- 幅 295px（端末本来の 412px の約 1.4 倍に拡大）で開かれた例があった。原因は、文字サイズではなく Chrome の「ページのズーム」。端末のフォントサイズを変えても直らなかった。
- 幅を決め打ちせず、開いたときに測って調整する。上部バーは `fitHeader()` で、「ロゴ+見出し → ボタンを詰める → 見出しだけ → ロゴだけ」の順に、必ず 1 行に収める。
- 確認するときは、幅 295px 前後と、330px 前後で見る。
- 原因が分からないときは、推測で直さず、`innerWidth`・`devicePixelRatio`・rem の px を端末で出して測る（一時的な確認用の表示で解決した）。

## 最初の画面も「枠に収める処理」の対象にする

- 文字を枠に合わせる `fit()` が、最初の画面（まだ何も表示していない状態）では働かず、狭い画面で案内文がはみ出した。パソコンの広い画面では気づけなかった。
- 状態ごとに、文字が枠に収まるか確かめる。

## Service Worker は、保存分を先に出すと更新が遅れる

- 保存済みの画面を先に出す作りだと、新しい版は 2 回目以降の起動まで出ない。
- `sw.js` は、ネットワーク優先にした。つながるときは最新を取って保存し直し、3 秒で取れないか失敗したときだけ保存分を出す（機内モードでも起動できる）。
- `index.html` などを変えたら、`sw.js` の `CACHE` のバージョンを上げる。

## 作業の進め方

- 公開したものを人の端末で確かめてもらうときは、「アプリを完全に閉じて開き直す」まで案内する。
- `index.html` を python などで書き換えるときは、エスケープ（`\b` が制御文字になるなど）に注意し、書き換え後に `node` で構文を確かめる。
- 入力欄にボタンや注意書きを足すと、開いたときに返事の一覧が潰れる（幅 295px・高さ 640px で、一覧の高さが 10px になった）。入力欄を開いている間は、ボタン側全体を縦にスクロールさせ、一覧は最低 8.5rem 確保する。入力欄まわりを変えたら、開いた状態の一覧の高さも測る。
- 長い python の書き換えスクリプトは、シェルに直接貼らず、ファイルに書いて `python -I` で実行する（引用符でシェルが落ちた）。
- ビルトインブラウザは、localhost の Service Worker を受け付けない。Service Worker は、公開 URL か、実機で確かめる。
